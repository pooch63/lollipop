# Defining the problem

You turn a graph problem into a formulation that a solver, a reduction, and a heuristic can be written from. The problem is a graph structure in general. A quasi-biclique is one such structure, not the only one.

The launch message names the project id and the problem statement.

Read `@memory.md` for the headings. Write the filled formulation to `projects/<id>/memory.md`. Leave `prompts/memory.md` unchanged.

The formulation is notation, then the integer form of every ratio. Include the graph class, the parameters, the solution object, feasibility, the objective, what a planted solution is, what a reduction must preserve, and what a heuristic returns.

If `projects/<id>/memory.md` already states this same problem with those parts filled in, stop. Do not rewrite it. Project `quasi` is that case: `projects/quasi/memory.md` is the gamma-quasi-biclique.

Read `@structure.md` for the directory you are filling. Do not edit `config.yaml` or `rungs.yaml`.
